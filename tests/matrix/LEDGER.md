# The combination ledger

One row per landed matrix cell: the bug/feature origin, the landing date, and
the invariant (or refusal contract) the cell pins. The matrix accretes by
construction — a bug fix or a feature lands its reproducing combination as a
new cell (the contributor duty: [CONTRIBUTING.md](../../CONTRIBUTING.md),
"fix a bug, add the cell") — and every build proves the whole current set.
The visible contract is the checkbox registry in
[issue #150](https://github.com/shsingh/pqscan/issues/150)'s body: one
checkbox per cell, the runner's per-build run comment proving the cells, green
cells ticked with the proven build sha in that body's footer, and an unticked
checkbox standing as the drift signal the next build must clear. This file is
the ledger behind those boxes.

One truth for what is valid: the shared domain table
[`domains.json`](domains.json) (this directory) — 28 array parameters, 7
constraint rows over the prereq / conflict / alias / meta-exclusion classes —
consumed by both the covering array and the battery's sampler. The chain
inputs are the pinned captures under
[tests/fixtures/chains/README.md](../fixtures/chains/README.md), the
pinned-command doctrine home (exactly one pinned capture command per adapter
input dialect, version-stamped in the fixture header). Upstream authority for
the surface itself is PQ-52's
[surface census](../../docs/surface-census.md).

Landing dates below are the merge dates of the landing changes; the whole
initial set landed 2026-10-20 (the three matrix PRs merged the same day).

## The whole-argv invariant battery (PQ-54) — one suite row

Origin: the combination invariants over the unenumerated space — issue
[#148](https://github.com/shsingh/pqscan/issues/148), PR
[#155](https://github.com/shsingh/pqscan/pull/155). Sources of truth:
[`battery_test.go`](battery_test.go) with
[`harness_test.go`](harness_test.go) (the shared materializeToken helper).
The suite rides the shared domain table and the real loopback fixture.

| Suite | Landed | Pins |
|---|---|---|
| `battery` | 2026-10-20 | 2 fixed seeds (`20261020`, `8675309`) × 200 constraint-repaired valid whole-argv vectors per seed, run against the real binary; the six invariants below |

The six invariants no valid combination may violate, re-checked per run:

1. the documented exit-0 class for every sampled vector (valid by
   construction: the sampler repairs the table's prereq/conflict classes);
2. stdout carries the selector's records ONLY — schema-1-valid on machine
   formats against the published contract
   ([docs/schema-v1.json](https://github.com/shsingh/pqscan/blob/main/docs/schema-v1.json)),
   grammar-parsable on the text/urls streams, and strictly no engine-note
   line in the record stream (notes are stderr-side, the output- and
   chainability dialect rule);
3. `-explain` renders iff text resolved — asserted in both directions;
4. `-o` is the single sink (stdout empty beside it): it writes every record
   and the WAL, and a `-resume` round-trip recovers a set-equal record set
   (equality derived from the parsed sets, never a pinned count);
5. dedupe: one record per host:port across all source composition
   (`-u` / `-l` / `-from-naabu` / `-from-httpx` / `-from-nuclei` / `--`
   with the expanded stdin line);
6. multiple format selectors compose per the documented precedence (the last
   selector on the line wins) without error; the `-json`/`-jsonl` alias pair
   is conflict-free (both-on normalizes to one well-formed schema-1 stream).

Seed rotation: `PQ54_SEEDS` appends extra seeds each run (the fixed pair
always runs); the suite's wall budget holds 2× headroom over the CI-observed
wall — shrink the per-seed sample count if ever over it, never an invariant.

## The constraint vocabulary (the shared domain table)

The domain table's 7 constraint rows across 4 classes — both the array runner
and the battery's sampler honor them, and a repaired row records the class it
exercised:

- prereq — `-explain` on requires `-text` on
  ([the output and chainability contract](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#57-output-and-chainability))
- prereq — `-deep full` requires `-mode deep`
  ([the deep-mode scheduling plan](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#74-deep-mode-scheduling-the-probe-plan-dag))
- prereq — `-resume` requires `-o` file
  ([targeting and discovery](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#51-targeting-and-discovery))
- prereq — the source floor: at least one of `-u`, `-l` (file or stdin), the
  `-from-*` adapters, or `--` with the expanded stdin line
  ([targeting and discovery](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#51-targeting-and-discovery))
- conflict — `-quic-always` and `-quic-off` are mutually exclusive on one
  command line
  ([the protocol coverage matrix](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#53-protocol-coverage-matrix))
- alias — `-json` is `-jsonl`'s documented alias: both-on is a well-formed
  normalization, never a conflict
  ([the output and chainability contract](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#57-output-and-chainability))
- meta-exclusion — `-version` / `-completion` never join a scan-plane row
  ([the CLI surface](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#8-cli-surface))
