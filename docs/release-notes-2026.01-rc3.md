# pqscan 2026.01-rc3

The successor release candidate to [`2026.01-rc2`](2026.01-rc2.md). rc3 is the
quality-gate day: the CLI surface went through a three-way parity census
against the reference tools, every documented flag combination is
machine-run on CI, the chain adapters read version-stamped pinned captures,
and error records finally meet the same schema contract success records
have had since schema 1.

## The surface census: the documented surface is the real surface

The three-way census over the CLI surface — every spec row against its
USAGE.md row against the implemented state — landed in
[docs/surface-census.md](surface-census.md)
([issue #146](https://github.com/shsingh/pqscan/issues/146), PR
[#151](https://github.com/shsingh/pqscan/pull/151)):

- Planned-list cuts: `-quic` (superseded by the shipped `-quic-always` /
  `-quic-off` pair; the bare flag has no independent reading) and `-verify`
  (owned by no contract row; naabu's `-verify` is a captured name collision)
  leave the planned surface.
- The spec's never-needed negative rows are cut: `-stream`, `-ja4`,
  `-ca-bundle`, `-no-ptr`, `-no-color`.
- `-jarm` earned its documented row (httpx v1.12.0's `-jarm` is the captured
  convention) and stays a documented-ahead row in the planned surface.
- `-from-nuclei` entered the surface and shipped in this same wave (below).

Every parity claim is a captured help line, version-stamped offline
(captures: naabu 2.6.1, httpx v1.12.0, subfinder v2.16.0, nuclei v3.11.1 —
help/version surfaces only, no scanned targets). The verdict rule: a row
earns its place iff a contract row plus a reference-tool or chain contract
needs it; it is cut iff superseded by a shipped sibling or owned by nothing.

## The flag matrix

PQ-53 ([issue #147](https://github.com/shsingh/pqscan/issues/147), PR
[#152](https://github.com/shsingh/pqscan/pull/152)): a generated pairwise
covering array over the CLI surface — the domain table
(`tests/matrix/domains.json`), 20 cases (`tests/matrix/cases.jsonl`) —
regenerated by `scripts/gen_flag_matrix.go` behind a self-verifying gate: CI
re-pins the array, regenerates, and compares three-way. The `flag-matrix`
context joined the required checks: every change is machine-run against the
documented combinations.

## The combination batteries

PQ-54 ([issue #148](https://github.com/shsingh/pqscan/issues/148), PR
[#155](https://github.com/shsingh/pqscan/pull/155)): the whole-argv property
battery over the unenumerated input space — two fixed seeds × 200 vectors
per `tests/matrix/battery_test.go` run (rotatable via `PQ54_SEEDS`; the
fixed seeds always run) — plus the documented exit-64 refusal classes as
deliberate battery rows whose expected text quotes the binary's own refusal
lines. Pooled and calibrated to the CI runner's wall budget.

## The chain matrix and the adapters

PQ-55 ([issue #149](https://github.com/shsingh/pqscan/issues/149), PR
[#158](https://github.com/shsingh/pqscan/pull/158)): `-from-nuclei` reads
the pinned capture (`nuclei -l hosts.txt -silent -j` — one JSON finding per
line, the matched-at host:port with the url as the fallback, scheme and path
stripped) into the one composition shared with `-u` / `-l` / `--` and the
other adapters, deduped by host:port. The adapters' consumer cells joined
the matrix run, and every adapter input dialect is pinned by a
version-stamped capture before its parse contract — the httpx `-csv`
dialect's real captured shape is the pinned reality the docs quote.

## The combination ledger

PQ-56 ([issue #150](https://github.com/shsingh/pqscan/issues/150), PR
[#160](https://github.com/shsingh/pqscan/pull/160)):
[tests/matrix/LEDGER.md](../tests/matrix/LEDGER.md) pins landed truth — one
checkbox per matrix cell in the issue registry, a per-cell PASS/SKIP line
posted per build, green cells ticked with the proven commit, and every fix
or feature landing its own cell in the same change.

## The doc-reference scrub

PQ-57 ([issue #153](https://github.com/shsingh/pqscan/issues/153), PRs
[#161](https://github.com/shsingh/pqscan/pull/161) and
[#163](https://github.com/shsingh/pqscan/pull/163)): the tool's user-facing
strings carry zero PRD references — no doc-file paths, no internal tokens,
no issue-register mentions anywhere user-facing. The surface audit gained a
zero-reference census (it renders the live surface and greps one inventory:
doc-file paths, `.md` tokens, PQ-N ids, status words), so a re-introduced
reference fails CI. The sweep is recorded in the spec's test-and-verification
chapter ([section 10](https://github.com/shsingh/pqscan/blob/main/docs/spec.md#10-test-and-verification-strategy)).

## Errors meet the record contract

PQ-60 ([issue #157](https://github.com/shsingh/pqscan/issues/157), PR
[#162](https://github.com/shsingh/pqscan/pull/162)): schema-required blocks
emit unconditionally on BOTH record classes — the handshake zero-halves and
the quic block appear on error-class and skipped runs exactly as on success
records (`omitempty` is forbidden on the schema's required field list), and
`TestErrorRecordSchemaContract` pins the uniform contract against the
published [docs/schema-v1.json](schema-v1.json). The `error.*` goldens
regenerated; the success-class goldens stayed byte-identical — the cure did
not disturb the valid shapes.

## The recipes and the docs re-capture

PQ-58 ([issue #154](https://github.com/shsingh/pqscan/issues/154), PR
[#164](https://github.com/shsingh/pqscan/pull/164)): every recipe line on
the site is executed live against the current surface and its Observation
quotes that exact run's output; the external-input examples pin the
reference tools' captured dialects (subfinder v2.16.0, httpx v1.12.0,
nuclei v3.11.1, version-stamped in the fixtures).

## The performance and size surfaces move with the cut

From rc3 on, every release build is preceded by the release-prep pass
([issue #156](https://github.com/shsingh/pqscan/issues/156)): the throughput
SLO + size + resume suites re-run live on the to-be-cut tree, and README's
SLO cell, the site's performance surfaces and the size ledger
([docs/size-ledger.md](size-ledger.md)) carry the measured numbers — the
release gate then verifies rather than prepares. At this cut the throughput
SLO cell stands at 2,952 h/s (re-run 3,026; the engine's handshake planes
are unchanged since 2026.01-rc2 and the CI runner's same-day readings
bracket the documented cell), while the size ledger moved to the measured
tree: 7,131,298 bytes CI-enforced (go1.26.0), 7,643,296 bytes local at
go1.27.2.
